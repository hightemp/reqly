# Reqly — Product Requirements Document

> Язык документа: русский. Язык кода, идентификаторов, коммитов, комментариев и UI-строк по умолчанию: английский.
> Статус: черновик v0.1 · Дата: 2026-10-17 · Лицензия проекта: MIT

---

## 1. Обзор

**Reqly** — кроссплатформенный API-клиент, аналог Insomnia/Postman. Поставляется в двух вариантах с одним UI:

1. **Desktop / Mobile**: приложение на Tauri 2 для Linux, Windows, macOS и Android.
2. **Server**: самостоятельный сервер на Rust (axum), который отдаёт тот же UI в браузер. Запросы к API отправляются с сервера. Поддерживается однопользовательский и многопользовательский режим с совместной работой в реальном времени.

### 1.1. Цели

- Быстрый, лёгкий и полностью кастомизируемый клиент без «браузерного» вида: все контролы свои, темы, хоткеи.
- Паритет функций desktop и web: одна кодовая база UI и одно Rust-ядро.
- Совместимость с экосистемой: импорт и экспорт Insomnia, Postman, cURL, OpenAPI, HAR, Bruno.
- Возможность командной работы через собственный сервер (self-hosted).

### 1.2. Целевая аудитория

- Backend- и frontend-разработчики, QA, DevOps.
- Команды, которым нужен self-hosted аналог облачных workspace Postman/Insomnia.

### 1.3. Не цели (на текущий момент)

- Облачный SaaS от проекта: только self-hosted сервер.
- Дизайнер OpenAPI-спецификаций (как Insomnia Design) и mock-серверы: в бэклоге.
- Система плагинов: в бэклоге.

## 2. Термины

| Термин | Значение |
|---|---|
| Workspace | Верхний уровень. Единица доступа и совместной работы, содержит коллекции, глобальные окружения и cookie jar. |
| Collection | Набор папок и запросов внутри workspace. Имеет свои окружения (base + sub). |
| Folder | Папка в коллекции, может быть вложенной. Может задавать общие headers, auth и переменные. |
| Request | Запрос одного из видов: HTTP, GraphQL, WebSocket, SSE, gRPC. |
| Environment | Набор переменных. Бывает global (workspace), base и sub (collection), folder. |
| Response record | Сохранённый результат выполнения запроса (запись истории). |
| Core | Общее Rust-ядро, которое используют desktop и server. |
| Command | Типизированная операция ядра (RPC), которую вызывает UI через транспорт. |
| Transport | Слой UI для вызова команд: Tauri `invoke` в desktop, HTTP + WebSocket в web. |

## 3. Принципы

1. **Один UI, одно ядро.** Логика (HTTP, хранилище, шаблоны, импорт и экспорт, скрипты) живёт в Rust. UI тонкий: состояние, отображение, ввод.
2. **Паритет desktop и web.** Одна фича реализуется один раз в core и доступна обоим вариантам. Отличия (файловые диалоги, окно) изолированы за интерфейсами платформы.
3. **Полностью кастомный UI.** Никаких нативных `<select>`, `alert`, `confirm`, системных скроллбаров и тултипов. Исключение: системные диалоги выбора файлов в Tauri.
4. **TDD.** Любая задача начинается с теста (red → green → refactor). Критерии приёмки формулируются так, чтобы их можно было превратить в тесты.
5. **i18n с первого дня.** Все строки UI идут через словари (en, ru). Хардкод строк запрещён линтером.
6. **Доступность.** Полная навигация с клавиатуры, ARIA-роли, видимый фокус, контраст в темах не ниже WCAG AA.
7. **Готовность к sync и collab.** Модель данных с первого этапа содержит UUIDv7, версии, временные метки, soft delete и fractional ordering, чтобы этапы 7 и 10 не потребовали миграции модели.

### 5.3. Контракт UI ↔ ядро

- Все операции описываются в `reqly-api` как типизированные команды: `Command { name, Input, Output, Error }`, например `request.create`, `request.send`, `tree.move`.
- События (push от ядра): прогресс отправки, стриминг сообщений (WS, SSE, gRPC), изменения сущностей (для collab и нескольких вкладок), presence.
- TypeScript-типы генерируются из Rust (`ts-rs`). CI проверяет, что сгенерированные файлы актуальны.
- **Desktop:** каждая команда — Tauri command; события — Tauri events.
- **Server:** `POST /api/v1/cmd/{name}` (JSON) и WebSocket `/api/v1/ws` для событий и стриминга. Пользователь допустил REST или WS. Выбран RPC-over-HTTP плюс WS: команды остаются идентичными desktop, а WS нужен в любом случае для collab и стриминга.
- **Contract tests:** один набор тестов команд прогоняется через оба адаптера.

### 5.4. Хранилище

- **SQLite** через `sqlx` с миграциями. FTS5 для поиска по имени, URL, описанию и телу.
- Большие тела ответов и запросов (по умолчанию > 256 KB) хранятся во внешнем blob store (content-addressed файлы), в БД лежит ссылка.
- Desktop: БД в каталоге данных приложения. Server: каталог из конфигурации (`REQLY_DATA_DIR`).
- Слой репозиториев за трейтами, чтобы позже добавить PostgreSQL для сервера (бэклог).
- Автосохранение: debounce 500 мс плюс явное `Ctrl+S`. Если автосохранение выключено в настройках, у вкладки отображается индикатор «не сохранено».

### 5.5. HTTP-движок

Требования: timeline с сырыми запросом и ответом, HTTP/1.1, HTTP/2, HTTP/3 (опционально), прокси (HTTP, HTTPS, SOCKS5), клиентские сертификаты, кастомный CA, Digest, NTLM, AWS SigV4, отмена запроса, метрики времени (DNS, connect, TLS, TTFB, download).

**Решение принимается в спайке этапа 0 (ADR-002):**

| Вариант | Плюсы | Минусы |
|---|---|---|
| `curl` (libcurl, как в Insomnia) | Паритет с Insomnia: verbose-timeline, NTLM, Digest, SigV4, HTTP/3, все виды прокси, тонкие TLS-настройки | C-зависимость, сложнее кросс-компиляция (особенно Android) |
| `reqwest` / `hyper` | Чистый Rust, проще сборка под все платформы | Timeline, Digest, NTLM и SigV4 придётся реализовывать самим; меньше низкоуровневого контроля |

Предварительная рекомендация: libcurl со статической сборкой и rustls или OpenSSL, если спайк подтвердит сборку под Android. Иначе hyper. В любом случае движок скрыт за трейтом `HttpEngine`.

### 5.6. JS-движок для скриптов (этап 6)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **rquickjs** (QuickJS-ng) | ~1 МБ, быстрый старт, лимиты памяти и времени (interrupt handler), собирается под Android, ES2023 | Медленнее V8 на тяжёлых вычислениях (для скриптов запросов несущественно) |
| Boa | Чистый Rust, простая сборка | Ниже производительность и полнота стандарта |
| deno_core (V8) | Максимальная скорость и совместимость | +30–40 МБ к бинарнику, сложная сборка под Android, тяжёлый рантайм |

Рекомендация: **rquickjs**. Итоговое решение подтверждается спайком (ADR-006): проверка сборки на всех платформах, лимитов и производительности.

### 5.7. Безопасность

- **Server, SSRF:** запросы отправляются с сервера, поэтому нужна настраиваемая политика исходящих соединений: allowlist и denylist хостов и CIDR, по умолчанию запрет `169.254.0.0/16` (metadata). Блокировка приватных сетей настраивается, поскольку для self-hosted она часто нужна выключенной.
- **Server, авторизация:** режимы `none | token | multi` (см. 7.17). Пароли хешируются argon2id. Сессии через HttpOnly cookie. CSRF-защита. Rate limit на логин.
- **Секретные переменные:** флаг `secret`, маскирование в UI, исключение из экспорта по умолчанию, шифрование at-rest ключом из файла в каталоге данных. OS keychain пока не используется (в бэклоге).
- **Preview HTML-ответов:** sandboxed iframe без скриптов по умолчанию (переключатель в настройках).
- **Скрипты:** изолированная песочница, лимиты времени и памяти, без доступа к FS и сети, кроме явного API (`sendRequest`).
- **Файлы в серверном режиме:** файлы для multipart и binary загружаются в blob store сервера. В desktop хранится ссылка на путь плюс опциональное встраивание.

## 6. Модель данных

Общие поля всех синхронизируемых сущностей: `id` (UUIDv7), `created_at`, `updated_at`, `version` (монотонный счётчик), `deleted_at` (soft delete), `sort_key` (fractional index, строка).

```
Workspace ─┬─ GlobalEnvironment[]           (этап 2)
           ├─ CookieJar ── Cookie[]
           ├─ ClientCertificate[]
           ├─ Member[] (user_id, role)       (этап 7)
           └─ Collection[]
                ├─ Environment base ─ Environment sub[]   (этап 2)
                └─ Node tree:
                     Folder (parent_id, name, headers[], auth, vars, description)
                     Request (parent_id, kind, name, ...)
                          └─ ResponseRecord[] (история)
```

**Request** (общие поля): `kind` (`http | graphql | websocket | sse | grpc`), `name`, `description` (markdown), `settings` (переопределение глобальных), `auth`, `scripts` (этап 6), `tests` (этап 9).

**HttpRequest**: `method` (стандартные и произвольные), `url`, `query_params[]`, `path_params[]`, `headers[]`, `body`.

**Key-value строка** (params, headers, form fields): `{ id, enabled, name, value, description, type? (text|file) }`.

**Body**: `none | json | xml | yaml | text | html | form_urlencoded | multipart | binary | graphql (этап 5)`.

**Auth**: `inherit | none | basic | bearer | api_key | digest | oauth1 | oauth2 | aws_sigv4 | ntlm | hawk | asap | netrc | akamai_edgegrid` (этапы 1 и 4).

**ResponseRecord**: `request_id`, `request_snapshot` (отправленный запрос после резолва переменных), `status`, `status_text`, `http_version`, `headers[]`, `cookies[]`, `body_ref`, `body_size`, `headers_size`, `timings` (dns, connect, tls, ttfb, download, total), `timeline[]`, `error?`, `created_at`.

**Settings**: глобальные (приложение или пользователь), workspace-уровень, переопределения на уровне запроса.

## 7. Функциональные требования

Метки этапов: **[Э1]**, **[Э2]** и т. д.

### 7.1. Workspaces и коллекции [Э1]

- CRUD workspaces и коллекций. Переключатель workspace в верхней части сайдбара. Последний открытый workspace восстанавливается.
- Workspace-уровень: cookie jar, клиентские сертификаты, глобальные окружения (Э2).
- Коллекция: дерево папок и запросов, окружения (Э2), настройки по умолчанию.

### 7.2. Сайдбар [Э1]

Два режима, переключаются в настройках и быстрой кнопкой в шапке сайдбара:

**Режим «Дерево» (по умолчанию, как в Insomnia)**
- Единое дерево папок и запросов. У запроса отображается бейдж метода (цвет зависит от темы) или протокола.
- Раскрытие и сворачивание папок, состояние сохраняется.

**Режим «Категории + список»**
- Сверху дерево только папок (категорий), под ним список запросов. Между ними горизонтальный разделитель с изменяемой высотой.
- Клик по категории показывает в списке запросы этой папки **рекурсивно со всеми вложенными**, сгруппированные по подпапкам. Заголовок группы — относительный путь, например `users / admin`. Есть переключатель «плоский список».
- Корень коллекции — это категория «Все запросы».

**Общее для обоих режимов**
- Виртуализация: 10 000+ узлов без потери плавности.
- Поиск и фильтр (`Ctrl+Shift+F` в сайдбаре) по имени, URL и методу, с подсветкой совпадений. Префиксы-фильтры: `method:POST`, `url:/users`.
- Мультивыделение: `Ctrl/Cmd+клик`, `Shift+клик`, `Ctrl+A` в фокусе дерева.
- Drag & drop: перемещение и сортировка запросов и папок, перенос между папками, групповой перенос. Индикаторы «вставить до», «после» и «внутрь». Автоскролл и автораскрытие папок при наведении.
- Сортировка: ручная (по умолчанию) или по имени, методу, дате создания или изменения. Выбранная сортировка задаётся для каждой папки.
- Контекстное меню (кастомное), в том числе для группы выделенных узлов: New request, New folder, Rename (`F2`), Duplicate (`Ctrl+D`), Cut (`Ctrl+X`), Copy (`Ctrl+C`), Paste (`Ctrl+V`), Delete (`Del`), Copy as cURL, Export selection (Э3), Settings (для папки), Reveal in tree (из режима списка).
- Cut, Copy и Paste работают между коллекциями и workspaces.
- Удаление с подтверждением (кастомный диалог) и Undo через тост. Удалённое попадает в корзину коллекции (soft delete), откуда его можно восстановить.

### 7.3. Вкладки (как в Postman) [Э1]

- Несколько открытых запросов во вкладках над редактором.
- Preview-вкладка: одиночный клик открывает временную вкладку (курсив), которая заменяется следующей. Двойной клик или редактирование закрепляют её.
- Индикатор несохранённых изменений (при выключенном автосохранении), индикатор выполняющегося запроса.
- Действия: закрыть (`Ctrl+W`), закрыть другие, закрыть справа, закрыть все, повторно открыть закрытую (`Ctrl+Shift+T`), дублировать, закрепить (pin), перетаскивание для сортировки.
- Переключение: `Ctrl+Tab`, `Ctrl+Shift+Tab`, `Ctrl+1…9`. Скролл при переполнении и меню списка вкладок.
- Набор вкладок восстанавливается после перезапуска (отдельно для каждого workspace).

### 7.4. Редактор HTTP-запроса [Э1]

- **URL-бар:** выбор метода (кастомный dropdown, стандартные методы и произвольный), поле URL с подсветкой. Двусторонняя синхронизация query-параметров с таблицей Params. Path-параметры `:id` выносятся в отдельную таблицу. Кнопка Send (`Ctrl+Enter`) и Cancel.
- Вставка cURL-команды в URL-бар автоматически разбирает её в запрос (с подтверждением).
- **Вкладки редактора:** Params, Body, Auth, Headers, Settings, Docs (markdown-описание). В заголовках вкладок отображаются счётчики (например, `Headers 3`).
- **Key-value редактор** (общий компонент): включение и выключение строки, описание, drag-сортировка, режим bulk edit (текст `key: value`), автодополнение имён и значений стандартных заголовков, для multipart — тип поля text или file.
- **Body:** все типы из раздела 6. Для текстовых форматов используется CodeMirror 6 с подсветкой, форматированием (`Ctrl+Shift+F`) и валидацией JSON. Для binary — выбор файла. При смене типа тела автоматически выставляется `Content-Type` (если пользователь не задал свой).
- **Наследование от папок:** заголовки и auth папок применяются к запросу (auth `inherit`). В UI показываются унаследованные заголовки (read-only, с указанием источника).
- Copy as cURL [Э1]; генерация кода на других языках [Э3].

### 7.5. Настройки запроса [Э1, Э4]

Задаются глобально, переопределяются на уровне коллекции, папки и запроса.

**Э1**
- Таймаут (connect и total), без таймаута.
- Следование редиректам вкл/выкл и максимальное число.
- Проверка SSL вкл/выкл, кастомные CA-сертификаты.
- Прокси: HTTP, HTTPS, SOCKS5, авторизация в прокси, список `no_proxy`, использование системного прокси.
- Клиентские сертификаты (PEM: cert + key, PFX/P12 + пароль) с привязкой к хосту (шаблон `*.example.com`, порт).
- Cookies: отправлять из jar вкл/выкл, сохранять из ответа вкл/выкл.
- Кодировать URL автоматически вкл/выкл.

**Э4 (дополнительно)**
- Выбор версии HTTP: auto, 1.1, 2, 2 prior knowledge, 3.
- DNS-переопределения (`host:port → ip`, аналог `--resolve`).
- Минимальная и максимальная версия TLS, SNI-override.
- Сжатие: `Accept-Encoding` автоматически и автоматическая распаковка.
- Keep-alive вкл/выкл.
- Максимальный размер ответа (обрыв загрузки при превышении).
- Unix domain socket как транспорт (Linux, macOS).
- Задержка перед отправкой.
- Network interface binding.

### 7.6. Авторизация

- **Э1:** Inherit (от папки), None, Basic, Bearer (с настраиваемым префиксом), API Key (в header или query).
- **Э4:** Digest, OAuth 1.0, OAuth 2.0 (Authorization Code с PKCE, Implicit, Password, Client Credentials, Device Code, Refresh; хранение и обновление токенов; встроенное окно логина в desktop и redirect-flow в web), AWS SigV4, NTLM, Hawk, Atlassian ASAP, Netrc, Akamai EdgeGrid, JWT Bearer (генерация и подпись токена).

### 7.7. Просмотр ответа [Э1]

- **Шапка:** цветной бейдж статуса, время (с детализацией по фазам в тултипе: DNS, connect, TLS, TTFB, download), размер (тело и заголовки, сжатый и распакованный).
- **Вкладки:**
  - **Body:** режимы Pretty, Raw и Preview. Автоопределение по `Content-Type`. Preview поддерживает HTML (sandbox iframe), изображения, PDF, аудио и видео, SVG. Для текста есть выбор кодировки, перенос строк, поиск (`Ctrl+F`), сворачивание блоков JSON/XML.
  - **Filter:** JSONPath, jq (для JSON), XPath (для XML). Поле фильтра под телом, как в Insomnia, с историей фильтров.
  - **Headers:** таблица и копирование.
  - **Cookies:** cookies, установленные ответом.
  - **Timeline:** сырой запрос (с резолвом переменных) и ответ, TLS-информация, информация о соединении, редиректы.
- Действия: копировать тело, сохранить тело в файл, сохранить ответ как пример, очистить.
- **Большие ответы:** pretty-подсветка до порога (по умолчанию 5 МБ, настраивается). Выше порога показывается сообщение с кнопками «Показать raw (усечённо)» и «Сохранить в файл». Тело загружается в UI по частям, UI не блокируется.
- Стриминг тела: прогресс загрузки и кнопка отмены.

### 7.8. История ответов [Э1]

- Каждая отправка создаёт `ResponseRecord`. Выпадающий список истории в панели ответа: время, статус, длительность. Можно выбрать прошлый ответ и сравнить два (diff — бэклог).
- Лимиты (настраиваются): N последних записей на запрос (по умолчанию 20), общий лимит размера (по умолчанию 1 ГБ), срок хранения (по умолчанию не ограничен). Очистка выполняется в фоне.
- Очистка истории для запроса, папки или коллекции.
- Глобальная история отправок (журнал всех запросов workspace) с поиском.

### 7.9. Cookies [Э1]

- Cookie jar на workspace. Автоматическое сохранение из `Set-Cookie` и отправка по правилам domain, path, secure и expiry.
- Менеджер cookies (модальное окно): просмотр, поиск, добавление, редактирование и удаление, очистка всего.

### 7.10. Переменные и окружения [Э2]

**Уровни и приоритет** (от низшего к высшему; более высокий перекрывает):

1. Global environment (workspace), активный набор.
2. Collection base environment.
3. Collection sub-environment (активное: dev, stage, prod…).
4. Переменные папок (от внешней к внутренней).
5. Переменные запроса (локальные).
6. Runtime-переменные, установленные скриптами (Э6), в рамках сессии или прогона.

- Переменные типизированы как JSON-значения (строки, числа, объекты, массивы), как в Insomnia. Допустимы вложенные обращения: `{{ _.api.host }}`.
- **Синтаксис:** `{{var}}` и совместимый с Insomnia `{{ _.var }}`. Template tags: `{% tag args %}` (совместимость с импортом Insomnia) плюс функциональный синтаксис `{{$name(args)}}`.
- Цвет у окружения отображается в UI (полоска или бейдж активного окружения, как в Insomnia).
- **Редактор окружений:** табличный и JSON-режим, флаг `secret` (маскирование, исключение из экспорта).
- **Подсветка в полях (как в Insomnia):** переменные отображаются «пилюлями» во всех полях (URL, headers, body, auth). Найденная переменная подсвечивается своим цветом, ненайденная — цветом ошибки. По наведению видно превью значения. По клику открывается inline-редактор тега.
- **Автодополнение** по `{{`: переменные (с указанием уровня-источника), теги, faker-функции.
- Резолв происходит в Rust-ядре. UI получает превью через команду `template.preview`.

### 7.11. Faker и template tags [Э2]

**Faker**
- Синтаксис: `{{$faker.<category>.<method>}}`, например `{{$faker.person.firstName}}` или `{{$faker.internet.email}}`, с аргументами: `{{$faker.number.int(1, 100)}}`. Нейминг категорий соответствует faker-js, так легче для пользователей.
- Алиасы динамических переменных Postman (`{{$guid}}`, `{{$timestamp}}`, `{{$randomFirstName}}` и т. д.) поддерживаются для совместимости импорта.
- Локаль данных выбирается в настройках коллекции или глобально: en, ru (дальше другие). Генерация выполняется в Rust (crate `fake`). Для ru, если в `fake` нет нужной локали, используются собственные датасеты (имена, фамилии, города, улицы, телефоны в российском формате).
- Каждое вычисление генерирует новое значение. Режим «зафиксировать значение на время отправки» означает, что одна переменная в одном запросе даёт одинаковое значение.

**Template tags (паритет с Insomnia)**
- Response chaining: значение из ответа другого запроса (body через JSONPath или XPath, header, raw, url) с политикой «никогда, всегда, если нет ответа, если старше N секунд» повторно отправлять запрос-источник.
- base64 encode/decode, url encode/decode, hash (md5, sha1, sha256, sha512, HMAC), uuid (v4, v7), timestamp и now (форматы, ISO, unix, кастом), random (int, float, string, regex), prompt (запросить значение у пользователя при отправке; в web через кастомный модал), file (содержимое файла), cookie (из jar), jsonpath над переменной, request (значение из текущего запроса: url, header и т. п.), os (desktop), JWT (encode, decode).
- Для каждого тега есть GUI-редактор аргументов с live-превью.

**Импорт**

| Формат | Приоритет |

- **Отчёт о неподдерживаемом:** скрипты Postman (до Э6), неподдерживаемые протоколы и auth, потерянные поля. Отчёт можно скопировать или сохранить. При импорте ничего не теряется молча.

- Round-trip тесты: импорт → экспорт → импорт даёт эквивалентные данные.

### 7.13. Генерация кода [Э3]

- Модальное окно «Generate code» и «Copy as…» в контекстном меню.
- Таргеты: cURL (bash, cmd, PowerShell), wget, HTTPie, JavaScript (fetch, axios, XHR), Node.js (http, undici), Python (requests, httpx, http.client), Go (net/http), Rust (reqwest), Java (OkHttp, HttpClient), Kotlin (OkHttp), C# (HttpClient, RestSharp), PHP (curl, Guzzle), Ruby (Net::HTTP), Swift (URLSession), Dart (http), PowerShell (Invoke-RestMethod).
- Опции: резолвить переменные или оставить шаблоны, включать auth, формат с отступами.

### 7.14. Протоколы [Э5]

- **GraphQL:** редактор запроса с подсветкой и автодополнением по схеме (introspection и загрузка из файла), variables (JSON), operation name, просмотр схемы (docs explorer), подписки через WS (`graphql-ws`).
- **WebSocket:** connect и disconnect, заголовки и auth при handshake, отправка сообщений (text, JSON, binary), лог сообщений с фильтром и временем, сохранённые шаблоны сообщений, авто-reconnect (опция).
- **SSE:** подключение, поток событий (id, event, data), фильтр по типу события, reconnect с `Last-Event-ID`.
- **gRPC:** загрузка `.proto` (файлы и import paths) или server reflection, выбор сервиса и метода. Unary, server streaming, client streaming и bidi. Metadata, TLS, deadline. Тело сообщения задаётся в JSON с автодополнением по схеме.
- **Дополнительно:** Socket.IO, MQTT — отложены в бэклог (ADR-008, TASKS B1, B2).
- Все протоколы используют общие механизмы: переменные, auth (где применимо), настройки, история.

### 7.15. Скрипты [Э6]

- Pre-request и after-response скрипты на уровне коллекции, папки и запроса. Порядок выполнения: коллекция → папки (от внешней к внутренней) → запрос.
- **API `rq`:** доступ к запросу и его изменение (url, headers, body), ответ, переменные всех уровней (get/set/unset), `rq.sendRequest()`, `rq.test()` и `rq.expect()` (Э9), консоль (`console.log`, вывод в панель Console).
- **Шимы совместимости:** `pm.*` (Postman) и `insomnia.*`, чтобы импортированные скрипты работали без переписывания (в пределах поддерживаемого API).
- **Встроенные модули:** `crypto-js`, `uuid`, `chai`, `lodash`, `atob/btoa`, faker, `moment`-совместимые функции дат (минимальный набор).
- Редактор: CodeMirror с автодополнением по `rq` и `pm` (d.ts), сниппеты.
- Песочница: лимит времени (по умолчанию 5 с) и памяти, без доступа к FS и сети, кроме `sendRequest`.

### 7.16. Тесты, ассерты, Runner, CLI [Э9]

- **No-code ассерты:** таблица условий (status equals, время ответа меньше X, header существует или равен, JSONPath или jq-значение равно, содержит или соответствует regex, соответствие JSON Schema).
- **Скриптовые тесты:** `rq.test('name', () => { rq.expect(...)... })`, `pm.test`.
- Панель результатов тестов в ответе.
- **Collection Runner:** запуск коллекции или папки, выбор окружения, итерации, data-файл (CSV или JSON) для параметризации, задержка между запросами, остановка при ошибке, порядок выполнения. Отчёты: HTML, JSON, JUnit XML.
- **`reqly-cli`:** запуск коллекций из файла экспорта или с сервера (по токену) в CI. Exit code зависит от результата.

### 7.17. Серверный режим [Э1, Э7]

**Конфигурация:** переменные окружения и (или) `reqly.toml`: `bind`, `data_dir`, `auth_mode`, `public_url`, CORS, TLS (или работа за reverse proxy), лимиты загрузки, политика исходящих соединений (SSRF, см. 5.7), логирование.

**Режимы авторизации** (`REQLY_AUTH_MODE`):
- `none` [Э1]: без авторизации (только для localhost или доверенной сети, с предупреждением при старте на не-localhost).
- `token` [Э1]: один пользователь, вход по токену или паролю из конфигурации.
- `multi` [Э7]: многопользовательский режим (см. ниже).

**Многопользовательский режим [Э7]**
- Регистрация: открытая, по приглашению или только администратором (настраивается). Bootstrap первого администратора через env или CLI.
- Пользователи, сессии, смена пароля, API-токены (для CLI и sync).
- Workspace-членство с ролями `owner`, `editor`, `viewer`. Приглашения по ссылке и email (email — опционально, SMTP).
- Админ-панель: пользователи, workspaces, настройки сервера.
- SSO (OIDC) — бэклог.

**Совместная работа в реальном времени [Э7]**
- Изменения сущностей рассылаются через WS всем участникам workspace. Дерево, вкладки и редакторы обновляются без перезагрузки.
- Presence: аватары участников в шапке, индикатор «кто открыл этот запрос» в дереве и на вкладке.
- **Конфликты:** структурные поля (имя, метод, headers, настройки) разрешаются по принципу last-writer-wins на уровне поля, с версионированием и уведомлением, если ваше изменение перезаписали.
- **Текстовые поля** (URL, body, скрипты, описание) совместно редактируются через CRDT: Yjs на клиенте (`y-codemirror.next`) и `yrs` на сервере, с курсорами других участников.
- История ответов личная или общая (настройка workspace). По умолчанию личная.
- Audit log действий в workspace (бэклог).

### 7.18. Синхронизация desktop ↔ server [Э10]

- Desktop подключается к серверу (URL, логин или токен) и выбирает workspaces для синхронизации.
- Offline-first: локальные изменения пишутся в журнал операций и отправляются при подключении.
- Разрешение конфликтов по тем же правилам, что и в collab (LWW по полям и CRDT для текста). Диалог для неразрешимых конфликтов (например, удаление против изменения).
- Индикатор статуса sync, ручной «Sync now».
- Секреты по умолчанию не синхронизируются (опция).

- Ошибки ядра передаются как коды с параметрами, локализуются в UI.
- CI-проверка: все ключи присутствуют во всех словарях, нет неиспользуемых ключей, нет хардкод-строк в компонентах.

**Настройки [Э1]**
- Модальное окно или вкладка с разделами: General (язык, автосохранение, восстановление вкладок), Appearance (тема, плотность, шрифты, раскладка, режим сайдбара, рамка окна), Editor (табы, перенос строк, номера строк), Request defaults (раздел 7.5), Proxy и Certificates, History (лимиты), Keybindings, Data (каталог данных, бэкап, очистка), About.
- Поиск по настройкам.

### 7.20. Android [Э8]

- Адаптивная раскладка: сайдбар как drawer, запрос и ответ как переключаемые панели (сегмент-контрол), вкладки как список открытых.
- Touch-адаптация: размеры целей, long-press вместо правого клика для контекстного меню, свайпы.
- Ограничения: нет кастомного titlebar, выбор файлов через Android-диалоги, клиентские сертификаты через импорт файла.
- Функциональный паритет с desktop, кроме: Unix sockets, network interface binding, `os`-тега.

## 10. Процесс разработки

- **TDD** — обязательно:
  - Rust: unit-тесты рядом с кодом, интеграционные в `tests/`, snapshot-тесты (`insta`) для импорта, экспорта, codegen и timeline, property-тесты (`proptest`) для парсеров (cURL, шаблоны, URL).
  - UI: Vitest для stores, утилит и компонентов (testing-library). Playwright e2e против server-сборки. Smoke e2e desktop через `tauri-driver` (Linux, Windows).
  - Contract tests команд для обоих транспортов.
  - Тестовый HTTP-сервер (Rust) с эндпоинтами для echo, редиректов, cookies, задержек, больших тел, auth-схем, TLS и mTLS.
- **Определение готовности (DoD) задачи:** тесты написаны до кода и проходят; линтеры чисты; i18n-ключи en и ru; работает в desktop и web (если применимо); работает во всех встроенных темах; есть клавиатурная навигация; обновлены документация и CHANGELOG.
- **Git:** trunk-based, короткие ветки `feat/…`, `fix/…`, Conventional Commits, PR с зелёным CI.
- **ADR:** каждое значимое архитектурное решение фиксируется в `docs/adr/NNN-title.md`.
- **CI (GitHub Actions):** lint → unit (Rust, UI) → contract → e2e (server) → сборка desktop-матрицы (Linux, Windows, macOS) → Docker-образ. Начиная с Э8 добавляется Android-сборка. Релизы через теги.
