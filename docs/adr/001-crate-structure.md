# ADR-001: Crate structure and module boundaries

- Status: accepted
- Date: 2026-10-17

## Context

Reqly ships as a desktop app (Tauri 2) and as a server (axum); both open the
same Svelte UI in a webview or a browser. The logic must exist once, and every
feature must work in both without duplication.

## Decision

A Cargo workspace:

| Crate | Purpose | Depends on |
|---|---|---|
| `reqly-core` | Domain primitives (Id, SortKey, Meta, Clock), error model, domain model | — |
| `reqly-storage` | SQLite (sqlx), migrations, backup before migrating, repositories | core |
| `reqly-api` | UI ↔ core contract: commands, registry, events, TS type generation, contract suite | core, storage |
| `reqly-testserver` | Test HTTP(S)/mTLS server for integration tests | — |
| `apps/server` | axum: `POST /api/v1/cmd/{name}`, WS `/api/v1/ws`, embedded UI | api |
| `apps/desktop` | Tauri 2: `dispatch` command, events forwarded to the webview | api |

Later crates (`reqly-http`, `reqly-template`, `reqly-interop`, `reqly-protocols`,
`reqly-script`, `reqly-testing`, `reqly-sync`) are added stage by stage and wired
into `reqly-api`.

Rules:

- Shells (`apps/*`) contain no business logic, only transport.
- Every UI operation is a `Command` in `reqly-api` with serde and TS types. The
  TS types are generated by `ts-rs` into `ui/src/lib/api/generated/` when
  running `cargo test`; CI checks that the files are up to date.
- Errors are `CoreError { code, message, params }` and are localized only in
  the UI.
- The contract suite (`reqly-api::contract`, feature `contract`) runs over
  HTTP (server) and over Tauri IPC (desktop, mock runtime).

## Consequences

- A new feature is a command in `reqly-api` plus a service in a domain crate;
  both shells get it automatically.
- `reqly-api` becomes the assembly point, so its dependencies grow. This is
  fine as long as domain crates do not depend on `reqly-api`.
