# Скрипты

Скрипты — это JavaScript, который выполняется вокруг запроса:
**pre-request** скрипт — перед отправкой, **after-response** скрипт — когда
пришёл ответ. С их помощью вычисляют значения (метки времени, подписи,
токены), меняют запрос на лету, сохраняют данные из ответов в переменные и
проверяют ответы.

На этой странице — как работают скрипты. Полный список объектов и методов —
в разделе [API скриптов](help:script-api), примеры со всеми встроенными
библиотеками и готовые рецепты — в [Библиотеки и рецепты](help:script-libraries).

## Где находятся скрипты

- **Запрос**: вкладка **Скрипты** запроса, два редактора — pre-request и
  after-response.
- **Папка**: **Настройки папки… → Скрипты**. Выполняются для каждого
  запроса в папке, включая вложенные папки.
- **Коллекция**: **Скрипты коллекции…** в меню коллекции. Выполняются для
  каждого запроса коллекции.

Редактор подсказывает API (`rq.`, `pm.`), имена переменных и функции
faker-js.

## Порядок выполнения

Для одного запроса скрипты выполняются снаружи внутрь:

1. pre-request скрипт коллекции;
2. pre-request скрипты папок, от внешней папки к внутренней;
3. pre-request скрипт запроса;
4. _запрос рендерится (шаблоны заменяются значениями) и отправляется_;
5. after-response скрипт коллекции;
6. after-response скрипты папок, начиная с внешней;
7. after-response скрипт запроса.

Каждый скрипт видит изменения предыдущих: переменную, заданную скриптом
коллекции, может прочитать скрипт запроса.

## Pre-request скрипты

Pre-request скрипт работает с запросом **до** рендеринга шаблонов:
`rq.request.url` возвращает `{{base_url}}/orders` в том виде, как вы его
написали. Переменные, заданные скриптом, используются при рендеринге сразу
после него, поэтому здесь удобно готовить значения для `{{ шаблонов }}`.

```js
// Свежая метка времени и id запроса для {{ts}} и {{requestId}}
rq.variables.set('ts', Date.now());
rq.variables.set('requestId', require('uuid').v4());

// Изменить сам запрос
rq.request.headers.upsert({ key: 'X-Client', value: 'reqly' });
rq.request.url.query.upsert({ key: 'lang', value: 'ru' });
```

## After-response скрипты

After-response скрипт читает ответ, сохраняет то, что нужно следующим
запросам, и проверяет результат. Результаты тестов появляются на вкладке
**Тесты** ответа, вывод `console.log` — на вкладке **Консоль**.

```js
const body = rq.response.json();

// Сохранить токен для следующих запросов: {{token}}
rq.environment.set('token', body.token);

// Тесты
rq.test('статус 200', () => {
  rq.response.to.have.status(200);
});
rq.test('вернулось три элемента', () => {
  rq.expect(body.items).to.have.lengthOf(3);
});

console.log('пользователь', body.user.name);
```

## Переменные в скриптах

| Объект                   | Читает                                            | Пишет в                                          |
| ------------------------ | ------------------------------------------------- | ------------------------------------------------ |
| `rq.variables`           | все уровни, побеждает ближайший                   | переменные времени выполнения (см. ниже)         |
| `rq.environment`         | активное окружение                                | активное окружение (базовое, если активного нет) |
| `rq.collectionVariables` | базовое окружение коллекции                       | базовое окружение                                |
| `rq.globals`             | активное глобальное окружение                     | глобальное окружение                             |
| `rq.iterationData`       | текущую строку файла данных при запуске коллекции | —                                                |

**Переменные времени выполнения** (`rq.variables.set`) действуют для всех
запросов коллекции до перезапуска приложения и переопределяют все остальные
уровни. Они удобны для значений, которые не нужно сохранять. Их видно и
можно очистить в окне **Окружения** в разделе **Runtime (скрипты)**.

Значения могут быть строками, числами, булевыми значениями, массивами или
объектами. В шаблонах объекты и массивы превращаются в JSON.

## Асинхронный код

`await` работает на верхнем уровне скрипта. Скрипт завершается, когда
закончились все его таймеры и запросы.

```js
const res = await rq.sendRequest(rq.variables.replaceIn('{{base_url}}/health'));
console.log('health', res.code);

await new Promise((resolve) => setTimeout(resolve, 100));
console.log('через 100 мс');
```

## Ошибки и ограничения

- Ошибка **pre-request** скрипта отменяет запрос: он не отправляется, а
  ошибка и вывод консоли показываются и сохраняются в истории.
- Ошибка **after-response** скрипта появляется в **Консоли**; ответ
  сохраняется.
- Скрипт, который работает дольше **5 секунд** или занимает больше
  **64 МБ**, останавливается. Ожидание `sendRequest` и таймеров не
  считается.
- Скрипты выполняются в песочнице (QuickJS): нет доступа к файлам, сети
  (кроме `sendRequest`) и системе. `require()` даёт только
  [встроенные библиотеки](help:script-libraries).

## Скрипты Postman и Insomnia

`pm` и `insomnia` — тот же API, что и `rq`, поэтому скрипты,
импортированные из Postman и Insomnia, работают без изменений. Работают и
старые глобальные объекты Postman: `tests['name'] = условие`,
`responseBody`, `responseCode`, `postman.setEnvironmentVariable`. Скрипты
Bruno используют другой API и импортируются закомментированными.

```js
// Скрипт Postman работает как есть
pm.test('Status code is 200', function () {
  pm.response.to.have.status(200);
});
const jsonData = pm.response.json();
pm.environment.set('userId', jsonData.user.id);
```
